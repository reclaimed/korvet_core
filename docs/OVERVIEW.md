# Архитектура korvet_core: обзор

Документ отвечает на вопросы «как устроено ядро» и «какими терминами
оно оперирует». Справочник фасада — [MOTHERBOARD_API.md](MOTHERBOARD_API.md),
инструмент проверки — [korvet_core/minigui/README.md](../korvet_core/minigui/README.md),
формат трассы — [TRACE_FORMAT.md](TRACE_FORMAT.md), отложенные операции
дисковода — [FDC_PENDINGOP.md](FDC_PENDINGOP.md), клавиатура —
[KEYBOARD.md](KEYBOARD.md).

## Глоссарий: аппаратные термины

| Термин | Расшифровка | Смысл |
|---|---|---|
| ГЗУ / GZU | графическое запоминающее устройство | растровая видеопамять: 4 страницы × 3 плоскости × 16 КБ |
| АЦЗУ / ACZU | алфавитно-цифровое ЗУ | текстовый видеобуфер 1 КБ: 1024 × [символ, атрибут] |
| VIREG | видео-регистр (порт C ППР№1) | страница доступа/отображения ГЗУ, режим записи атрибута, широкий режим, выбор шрифта |
| NCREG | регистр цвета | послойный/цветовой режим записи плоскостей ГЗУ (WSEL/RSEL, WBIT, COLORMD) |
| VISST | видео-статус (PPI1-A бит 3) | триггер инверсии: бит атрибута, защёлкиваемый при чтении АЦЗУ |
| ВГ93 / VG93 | КР1818ВГ93 (аналог WD1793) | контроллер дисковода |
| ИРПС | интерфейс радиальный последовательный | «компорт» Корвета (КР580ВВ51А/8251A) |
| УСАПП | универсальный синхронно-асинхронный приёмопередатчик | БИС 8251A (ИРПС и ЛВС) |
| DRVREG | регистр дисковода (PPI1-B) | выбор привода/стороны/мотора (DS0-3, SIDE1, MOTOR, SDEN, D200) |
| LANADR | регистр адреса рабочего места (PPI1-A биты 4-7) | «перемычки» адреса РМУ в сети 1-15 |
| CE / CR / OL | counting element / count register / output latch | официальные термины i8253 (КР580ИК53) |
| TMRINT | выход прерывания таймера | IRQ5, положительный фронт OUT канала 2 |
| MON | сигнал включения двигателей НГМД | перезапускаемый одновибратор 3 с (запуск по фронту бита 5 DRVREG), IRQ7 по истечении |
| KDI | — | формат образа дискеты: 80×2×5×1024 = 819 200 байт |
| KB00–KB11 | линии клавиатурной матрицы | основное поле (KB00-07) + дополнительное (KB08-11) |

## 1. Три принципа

### 1.1. Ядро не знает о хосте

Внутри `korvet_core/` нет ни одного `fopen`, `std::thread`, сокета или
вызова ОС. Всё, что требует окружения, вынесено наружу четырьмя
механизмами:

| Механизм | Направление | Примеры |
|----------|-------------|---------|
| **Колбэки** | ядро → хост | `mb_log_callback_t`, `SerialByteOutCallback`, `PrinterByteCallback`, `TapeOutCallback`, `FdcPendingOpCallback`, `mb_trace_callback_t` |
| **Интерфейсы** | хост → ядро | `IFddImageAdapter` — единственный способ дать ядру образ дискеты |
| **Буферы** | хост → ядро | `load_data()` (ПЗУ/шрифт/mapper), `tape_set_input()` (полупериоды кассеты) |
| **Указатели** | хост → ядро | `fdd_set_image_adapter()`, `set_*_callback()` |

Хост сам читает файлы, сам решает, куда писать байты принтера, как
упаковывать LAN-поток в транспорт и когда играть звук позиционирования
головки. Ядро лишь честно эмулирует железо и отдаёт события.

### 1.2. Время — только такты CPU

Единица времени в ядре — такт процессора (2,5 МГц). Константы:

```
TICKS_PER_FRAME = 50000   // 1/50 с гостевого времени (кадр, VBLANK)
VBLANK_TICKS    = 8170    // тактов в зоне вертикального гашения
CPU_CLK         = 2500000 // частота процессора
```

Модель исполнения — **порциями**: хост вызывает `run_ticks(n)` /
`run_opcodes(n)` / `run_while(pred)` / `run_frame()`, ядро исполняет
целые инструкции (4–17 тактов) и возвращает управление. Между вызовами
состояние заморожено — идеальная модель для отладчика, ИИ-агентов и
детерминированных тестов. Позиция внутри кадра сохраняется между
вызовами: `run_ticks(30000) + run_ticks(20000)` == `run_ticks(50000)`.

Кассета тоже живёт в тактах CPU: полупериоды входного потока задаются
в тактах, пауза реле «кратковременного стопа» замораживает виртуальное
время ленты.

### 1.3. Точность по технической документации

Поведение каждого узла строится по первоисточникам:

- «Описание программно-доступных элементов ПЭВМ ПК8020»
  (НИИСЧЕТМАШ, 10.12.1986) — регистры, порты, константы, протоколы;
- комментарии к принципиальной схеме ПК8020 (pk8020.ru) — сигналы,
  одновибраторы, разводка портов;
- паспорта устройств расширения ЭУ8040/ММ8031/МД8030 — протоколы
  манипуляторов;
- описания БИС (КР580ВИ53/ВН59/ВВ55/ВВ51А, КР1818ВГ93) — семантика
  режимов и команд.

Где источники противоречат друг другу (вход канала 2 таймера: HBL
65,6 мкс по схеме против 50 Гц по описанию элементов), выбор вынесен
в конфигурацию хоста, а противоречие зафиксировано в документации.
Имена внутренних переменных сохраняют обозначения документации БИС
(`dsk_vg()`, `cnt_ready_`, `counting_element`) — для построчной
сверки с первоисточниками.

## 2. Карта подсистем

```
                         Motherboard (фасад, singleton)
        ┌───────────┬────────────┬────────────┬────────────┬──────────┐
        │           │            │            │            │          │
      Cpu ──────► Memory ──► mapper (32×256) │          Video      Pic
     (i8080)      │    │                      │         ГЗУ/АЦЗУ   (i8259)
        │          │    └─ периферия ──► Fdc (ВГ93) ── IFddImageAdapter ──► [хост]
        │          │                 ► Ppi ×3 (i8255) ──► Timer(i8253) ──► Audio
        │          │                 ► Serial (8251A) ◄── Keyboard (8×13)
        │          │                 ► Lan            ──► Mouse / Joystick
        │          │                 ► Printer        ──► Tape
        └──────────┴──── trace/log/diag ───────────────────► [хост]
```

- **Memory** — маппер страниц: 32 регистра × 256 страниц, типы страниц
  RAM/ROM0-2/KEYBOARD/PORTBASE/REGBASE/ACZU/GZU. Порты периферии
  замаплены в адресное пространство — гость читает ВГ93, PPI и таймер
  как память (окно `0xFBxx` при системном регистре 16H).
- **Video** — 4 страницы ГЗУ × 3 плоскости × 16 КБ + АЦЗУ 1 КБ (символы
  + атрибуты), LUT-палитра 16 цветов → RGB. Рендер по dirty-флагам;
  двойная буферизация (`get_front_framebuffer()` через `shared_ptr`,
  zero-copy для GUI). Шрифт — два знакогенератора по 4 КБ (файл 8192
  байта); широкий режим — табличная развёртка `WEXPAND[16]` без
  отдельного буфера (экономия ОЗУ для RP2040).
- **Audio** — синхронная кадровая модель: тики канала 0 таймера
  копятся в буфер кадра, в конце кадра Брезенхем-даунсамплинг в 441
  сэмпл (20 мс, 22050 Гц, моно, int16). Не забрал кадр — кадр потерян;
  очередь — забота хоста. Гейт динамика — бит 3 PPI2-C (SNDEN):
  открывается только записью гостя.
- **Fdc** — счётная (по обращениям к портам) модель ВГ93 с мгновенным
  исполнением команд и опциональным режимом отложенных операций
  (PendingOp). Мотор — одновибратор MON на 3 с (общая линия, IRQ7 по
  истечении). Диск запрашивается сектором через `IFddImageAdapter`
  (нулевой номер сектора 0..4); сам файл образа ядро никогда не
  открывает.
- **Timer** — каналы 0/1 от 2 МГц (звук / задатчик скорости ИРПС),
  канал 2 — от источника конфигурации (HBL по умолчанию). BCD-счёт.
  Счёт начинается только после завершения загрузки CR. TMRINT — по
  фронту OUT канала 2.
- **Serial/Lan** — две КР580ВВ51А с двухфазным автоматом «слово
  режима → слово команды», приёмными очередями и прерываниями
  приёма/передачи (IRQ1/IRQ2 для ИРПС, IRQ3 для ЛВС).
- **Tape** — однобитовый канал по времени гостя: CASIN (уровень на
  момент опроса), CASOUT (трёхуровневый выход, события с тактом),
  реле стопа (заморозка виртуальной ленты). Модуляцию и формат блоков
  разбирает гостевое ПО — адаптер «тупой» по описанию элементов.
- **Ppi** — три КР580ВВ55: №1 (VIREG, DRVREG, сборка PPI1-A со
  статуса), №2 (данные принтера, гейт звука, кассета, строб), №3
  (порт расширения: мультиплексор ЭУ8040 — мышь ММ8031 / джойстик
  МД8030). Чтение портов A/B №3 учитывает направление из слова режима.

## 3. Модель кадра

Один «кадр» = 50 000 тактов = 1/50 с гостевого времени. Граница кадра —
единственное место, где ядро производит «медленные» события:

1. `begin_frame()` — VBLANK-начало: сброс счётчика кадра (бит VBLANK
   в PPI1-A вычисляется динамически от числа тактов).
2. …исполнение инструкций (по пути: трасса, тики таймера, детектор
   зависаний)…
3. `end_frame()` — IRQ4 (кадровое прерывание 50 Гц), генерация
   звукового кадра, опрос последовательной мыши, продвижение
   одновибратора MON / таймаутов ВГ93.

`run_frame()` = `execute_loop(бюджет 50000)`. `step()` — одиночная
инструкция отладчика (частичный кадр закрывается без конца кадра).
Видеокадр рендерится по явному вызову хоста `render_video_frame()` —
ядро само не решает, когда кадр «нужен» GUI.

## 4. Прерывания

Полная карта уровней (по описанию элементов):

| Уровень | Имя | Источник | Модель ядра |
|---|---|---|---|
| 0 | AUXINT | разъём расширения | `pic_trigger_irq(0)` хостом |
| 1 | SERINT1 | приёмник ИРПС | `Serial` (IRQ1) |
| 2 | SERINT2 | передатчик ИРПС | `Serial` (IRQ2) |
| 3 | LANINT | приёмник ЛВС | `Lan` (IRQ3) |
| 4 | PERINT | кадровый 50 Гц | `end_frame()` |
| 5 | TMRINT | канал 2 таймера | фронт OUT канала 2 |
| 6 | LSTINT | принтер | конец занятости `Printer` |
| 7 | MOTINT | выключение мотора НГМД | истечение MON в `Fdc::on_frame()` |

ВГ93 НЕ генерирует прерываний через PIC по завершении команд — INTRQ
чисто программный флаг (статус «не BUSY»), который ПЗУ опрашивает
через регистр состояния. Единственное прерывание узла НГМД — MOTINT.

ICW-автомат PIC: первый байт последовательности — всегда ICW2 (база
векторов); при SNGL=0 за ним поглощается ICW3; байт ICW4 в single-режиме
поглощается как OCW1 (IMR). Вектор прерывания для ПЗУ Корвета (шаг 4,
база 0xF7E0): `(0xF7<<8) | (A7-A5 биты) | (irq<<2)`.

## 5. Потокобезопасность

Ядро **однопоточно**: все вызовы фасада должен делать один поток
(поток эмуляции хоста). Единственный потокобезопасный синглтон —
`Logger` (защищён `std::mutex`; в сборке `KORVET_SINGLE_THREADED`
мьютекс заменён заглушкой `FakeLock` — сборка для bare-metal).
Колбэки вызываются синхронно из цикла исполнения — они обязаны быть
быстрыми и не блокировать.

## 6. Ограничения (осознанные)

- Звук — только пьезоизлучатель Корвета (канал 0 таймера через гейт
  SNDEN). Синтезатор ЗС8090 (проходная розетка ЭУ8040) не эмулируется:
  в доступных источниках поведение не описано.
- LAN — побайтовый порт без кадровой логики: семантика общей линии
  (каждый байт доставляется всем станциям) и транспорт — на хосте.
  Контроль чётности — опция `set_parity_check()`; при побайтовом
  транспорте между экземплярами эмулятора бит RPAR не выставляется
  (доставка не искажается). Соединение с реальным железом потребовало
  бы электрического уровня — за рамками чистой эмуляции.
- Скорости ИРПС/ЛВС не моделируются побитово: байты входят в очередь
  мгновенно (кадровая модель ввода мыши). ПО, калибрующее тайминги по
  скорости порта, увидит отличие; все известные драйверы
  синхронизируются по битам статуса/формату посылки.
- Клавиатура — матрица 8×13 (включая ПЧТ); раскладка «хост-клавиша →
  позиция матрицы» — целиком ответственность хоста (таблицы — в
  [KEYBOARD.md](KEYBOARD.md)).
- Дампы (`*_dump.cpp`) и `config.cpp` — host-инструменты с файловым
  I/O, в сборку ядра не входят (`KORVET_CORE_HOST_TOOLS`).
- `run_diagnostic()` и семейство — зарезервированный интерфейс,
  возвращает `MB_DIAG_SKIP` («не реализовано»).
